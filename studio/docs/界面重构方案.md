## 1. 定位回顾（为什么这么设计）

YXSpec Studio = **对话驱动的 ASPICE 流程驾驶舱**。

- **用户**：追踪协调型项目工程师（林汉飞这类）。看进度 → 判断下一步 → 派活 → 看结果 → 继续。**不代执行**。
- **核心闭环**：`看当前阶段 → 判断下一步 → 派活 → 看结果 → 继续`
- **设计原则（用户已拍板）**：对话优先级最高，任何界面都能对话；其余功能是辅助面板。

## 2. 现状诊断

### 2.1 产品视角：三个闭环断点

| # | 断点 | 现象 | 根因 |
|---|------|------|------|
| ① | **项目上下文不持续** | 切换器只在"未打开项目"空状态出现；打开后只能「关闭项目」→ 回空状态 → 再选 | 项目切换被当成"初始动作"，不是"常驻控件" |
| ② | **对话与阶段状态脱节** | 终端是主入口，但不知道自己在推进哪个阶段；派活后结果只看驾驶舱 | 对话终端无"目标阶段/门控"上下文 |
| ③ | **"下一步"双入口不贯通** | 驾驶舱有「建议下一步+一键派活」，终端有快捷芯片，两套不联动 | 两条派活路径互相独立，无回执互通 |

### 2.2 信息架构问题

- **侧边栏五张卡粒度不齐**：驾驶舱/产物图谱是"全流程视图"，任务/审查/Pipeline 是"单阶段视图"，平级混放无层级。
- **只读面板不跟随当前阶段**：任务看板默认写死 `task_sqt_case_design.md`，不自动定位到 current stage。

### 2.3 前端视角：空间与视觉

| # | 问题 | 严重度 |
|---|------|--------|
| ① | **对话被夹窄**：打开功能卡时终端压到 `min(460px,40vw)`，与"对话优先"直接相悖 | 🔴 高 |
| ② | **全局控件缺失**：最重要的"项目切换"藏在空状态，header/状态条/footer 全是展示性 chrome | 🔴 高 |
| ③ | **小屏不可用**：~900px 时右侧面板被压到 300px 以下 | 🟠 中 |
| ④ | **视觉杂**：字号三档混用（11px/14px/15px）；蓝层次过多；按钮语义色不统一；emoji 混排 | 🟡 低 |
| ⑤ | **错误链路短**：门控拦截 toast 一闪，无"跳到上游阶段"动作 | 🟡 低 |

## 3. 目标架构（一句话）

> **对话终端 = 工作台（常驻、占比大）；功能面板 = 可调用的抽屉（点击弹出、不挤对话）；项目切换 = 全局常驻控件（header 右上）。**

布局演变：

```
现状（三栏平铺，对话被夹）                    目标（工作台 + 抽屉）
┌────┬────────┬──────┐                    ┌────┬──────────────────────────────┐
│功能│ 对话   │ 功能 │                    │功能│        对话工作台            │
│卡栏│ 终端   │ 面板 │                    │卡栏│     （默认占主区域）         │
│    │460px   │      │                    │    │                              │
│    │ 被夹窄 │      │                    │    ├──────────────┐               │
└────┴────────┴──────┘                    └────┤  功能面板抽屉  │（遮罩/并排，┤
                                               │  不挤对话     │  不常驻）   │
                                               └──────────────┴──────────────┘
```

**关键变化**：
1. 功能面板从"常驻第三列"改为"可开合的抽屉/覆盖层"，对话区不再被挤压
2. 项目切换从"空状态"上移到 header 全局
3. 对话与阶段打通：终端顶部常驻"目标阶段 + 门控"上下文条

## 4. 分项方案

### P0-① 全局项目切换器（修复断点①）

**现状**：下拉只在 `!project` 时出现，打开后替换成"刷新/关闭"。
**改后**：header 右侧常驻"项目"控件，无论是否打开都在。

```
未打开项目：
  [⬇ 选择预置项目… ▾]  [输入或粘贴路径…]  [打开项目]

已打开项目：
  [AI培训相关/yxspec…/ai_tbox ▾]      // 点开下拉：
  │  ├─ 切换项目（列出全部预置项目，当前打勾）
  │  ├─ ────────
  │  ├─ 🔄 刷新当前项目状态
  │  ├─ 📋 复制项目路径
  │  └─ ❌ 关闭项目
  └──────────
```

- **实现**：抽出 `<ProjectSwitcher>` 组件（`src/components/layout/ProjectSwitcher.tsx`），替换 App.tsx header 现有区块
- **要点**：预置列表（已实现的 `/yxspec/projects`）始终可枚举；当前项目置顶/打勾；"关闭"降级为下拉内一个条目，不再是唯一出口

### P0-② 终端"目标阶段"上下文条（修复断点②）

**现状**：终端不知道自己在推进哪个阶段。
**改后**：终端顶部（连接状态行下方）加一条常驻上下文：

```
┌───────────────────────────────┐
│ ⚡ 执行终端 · 对话驱动 · 主入口   │
│ ├─ 已连接执行网关  (127.0.0.1:8787) │
│ ├─ 目标阶段：sqt_tr  ·  门控 ✓ 放行  │  ← 新增
│ │  （当前阶段） （gate.message 摘要） │
│ └─ 快捷指令：[阶段进度分析] [生成骨架]  │
│     （芯片按当前阶段动态生成）        │
└───────────────────────────────┘
```

- **实现**：`LLMConsole` 从 `useStageStore` 订阅 `currentStage` + 对应 gate；派生 `→ 目标阶段 sqt_tr · 门控 ✓`
- **附加价值**：派活回执进对话区（`🚀 已推进 sqt_tr，产物 5 份`），驾驶舱与终端同一真相源

### P1-③ 建议下一步贯通终端（修复断点③）

- 驾驶舱「一键派活」完成后，结果回填终端对话区（复用 `useAgentChat.setChat`）
- 终端快捷芯片按 `currentStage` 动态生成（不再写死三个）
- 两个派活入口共享同一 session/事件流，状态单向一致

### P1-④ 面板默认聚焦当前阶段

- 打开驾驶舱 → 自动滚动到 current stage 卡片
- 任务看板默认选中 `task_<currentStage>.md`（替代写死的 `task_sqt_case_design.md`）

### P1-⑤ 门控拦截可跳转

- toast/终端显示"先完成上游 X"时，可点击直接切到上游阶段并滚动到对应卡片

### P2-⑥ 视觉统一

| 项 | 现状 | 目标 |
|----|------|------|
| 字号 | 11px / 14px / 15px 混用 | 统一 base 14px，辅助 12px 单一档 |
| 主色 | blue-500 / blue-50 / emerald-600 混用 | 主操作蓝、主强调翠绿、中性灰，各归其位 |
| 按钮语义 | 打开=蓝-500 / 刷新=蓝-100 / 关闭=灰 | 主按钮=蓝-500、次按钮=灰-100、危险=红-50 |
| emoji | 与文字混排 | 保留少量状态图标，导航/操作不用 emoji |

### P2-⑦ 合并冗余 chrome

- 蓝色状态条并入 header（路径/分支/工期放 header 第二行），省出一整条高度

### P2-⑧ 小屏响应式

- 功能面板抽屉在 <1024px 时改全屏覆盖遮罩；终端占满
- 侧边栏 <800px 折叠成图标栏

## 6. 验收标准

- [ ] 打开项目后仍能切换项目（不用先关闭）
- [ ] 终端顶部能看到当前目标阶段 + 门控状态
- [ ] 一键派活后，终端对话区出现回执（阶段/产物数）
- [ ] 打开功能面板不挤压对话区
- [ ] 驾驶舱打开自动聚焦当前阶段；任务看板默认当前阶段文件
- [ ] 门控拦截提示可点击跳转上游
- [ ] tsc --noEmit 0 错误；浏览器模式 & Tauri 模式均正常
